## 📝 DEVLOG ENTRY #19 | PROJECT GLOSSY NOISE

**Дата:** 13.10.2026

**Статус билда:** Pre-Alpha / Mesh-Approach Approved

### 1. Гемини признал Mesh-подход

- **Изначально:** кубы — перестраховка по UV-развёртке и Pixel Grid (на кубах пиксель-арт по граням проще).
- **Теперь:** с утверждённым стандартом качества и связкой DeepSeek + Гемини — используем Mesh, цилиндры, сферы.
- **«Лестница из кубов»** — недопустима.

### 2. Утверждённые формы

- **Цилиндры** (8–12 граней) — корпуса, подставки, ручки, трубы.
- **Сферы** (сплюснутые) — выпуклые CRT-экраны, линзы.
- **Mesh-редактор** — произвольные формы.
- **Кубы** — только прямоугольные элементы (планки, панели, кнопки).

### 3. Работа с UV

- На цилиндрах и сферах пиксель-арт **может «плыть»**.
- **Решение:** контроль UV вручную (Per-Face UV), правка меша.
- **Связка DeepSeek + Гемини** позволяет контролировать процесс.

### 4. Следующий шаг

- Делать CRT-монитор через цилиндр + сплюснутую сферу + Mesh.
- Заменить «лестницу из кубов» на плавные формы.


## 📝 DEVLOG ENTRY #20 | PROJECT GLOSSY NOISE

**Дата:** 18.10.2026

**Статус билда:** Pre-Alpha / Texture Resolution Standard

### 1. Утверждён стандарт разрешения текстур

**База:** 256×256.
**Точечно:** 512×512 для конкретных задач.
**Мелочь:** 128×128 для мелких деталей.

**Почему так:**
- 256×256 — стильно для Y2K (не слишком пиксельно, не слишком «мыльно»), легко для Godot, достаточно для фактуры.
- 512×512 — только для экрана CRT (интерфейс, Глитчи, текст) и стикера (если текст нечитаем).
- 128×128 — для кнопок, щелей, мелких деталей.
- Все текстуры — степень двойки (MIP-карты).

**Чего не делаем:**
- Не гонимся за 512×512 на всё (Y2K — пиксель-арт, не реализм).
- Не делаем 1024×1024 (перебор по памяти, убьёт пиксель-арт).

### 2. Следующий шаг

- Делать текстуры CRT-монитора по этому стандарту.
- Экспорт `.glb` → Blender (Ctrl + J) → интеграция в Godot.

## 📝 DEVLOG ENTRY #26 | PROJECT GLOSSY NOISE

**Дата:** 24.10.2026

**Статус билда:** Pre-Alpha / Photobashing Pipeline

### 1. Утверждён пайплайн текстур: Фотобашинг

- **Концепция:** Для текстур корпуса (и других моделей) используем **чистокровный фотобашинг** через Krita. **Не** стандартные генераторы текстур.
- **Почему:**
  - **Аутентичность:** реальный пожелтевший пластик — сложная текстура (микротрещины, пятна, зерно). Генераторы не дают такого.
  - **Стиль Y2K:** ретро-железо, потрёпанное временем.
  - **Контроль:** ты решаешь, где царапина, где грязь, где блик.
  - **Экономия:** реальные фото — бесплатно.

### 2. Процесс

1. **Поиск фото:** свои фото (старый пластик), CC0-базы (Unsplash, Pexels, Poly Haven), сканы.
2. **Обработка в Krita:** импорт → подгон под 256×256 (или 512×512) → кроп → цветокоррекция (под палитру `#C2BCB0`) → убрать лишнее.
3. **Фотобашинг (на UV):** натянуть фото на UV → дорисовать кистями (царапины, грязь, потёртости по углам) → добавить зерно.
4. **Экспорт:** PNG (256×256 или 512×512) → импорт в Blockbench/Blender → натянуть на модель.

### 3. Исключение

- **Экран CRT:** фотобашинг для базовой текстуры (тёмное стекло, царапины), но **динамика** (статика, Глитчи, искажения) — через **шейдер** (позже).

### 4. Статус

- Пайплайн **утверждён**. Применяем **ко всем моделям** (не только к CRT).
- Зафиксировано в GDD (8.10), Визуальном стиле, AI_CONTEXT (6.2).

### 1. Утверждён пайплайн: готовые модели CC0 + адаптация

  - Адаптация (цвет, текстуры, детали) — проще и быстрее.
  - Это норма для инди-разработки (Valheim использовал аутсорс и готовые ассеты).

### 2. Процесс

1. **Поиск готовой модели:** Sketchfab (CC0), Kenney, Quaternius. Проверка лицензии.

### 3. Что можно/сложно

- **Можно:** цвет, материалы, пропорции, добавлять детали, удалять лишнее, перекрашивать текстуры.
- **Сложно:** полностью переделать геометрию (без ретопологии), поменять UV.

### 4. Исключение

- Простые модели (куб, цилиндр, кнопка) — можно в Blockbench (Auto UV).

### 5. Статус

- Пайплайн **утверждён**. Применяем к CRT-монитору и другим сложным моделям.
